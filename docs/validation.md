# Detection and operational validation

## Detection

A negative-binomial GLM estimates expected counts per site or district and outcome stream. Fits use up to 365 previous days and refresh every 28 days. The reference model includes day of week, annual seasonality, calendar flags and a log headcount offset. Sparse fits borrow estimates from the same site type. Missing counts are excluded. The API exposes expected values, central prediction intervals, exceedance probabilities and standardized residuals for release-eligible cells.

Fusion adds a capped hazard prior to capped, weighted outcome log-likelihood ratios. The comparison is a 1.9× increase against the fitted expectation. Correlated dust and PM2.5 inputs contribute a single maximum prior. Workplace streams have reduced weight alongside the primary outcome. GI has no weather prior. Available streams can support an Alert with reduced coverage in some cases. A missing feed supplies no term.

A Watch can trigger on exposure alone. Alert requires corroboration and two qualifying days in the last three, including the current day. Action requires stronger evidence and at least three days since the Alert. Three non-qualifying days rearm the unit and syndrome. Replayed scores operate at daily resolution.

The scan ranks site, linked site and district zones across trailing 1-, 3- and 7-day windows. An expectation-based Poisson likelihood ratio ranks eligible zones with releasable cells. The API provides a simulated maximum-score reference for the best zone. This is descriptive because the Poisson null simplifies overdispersion and the eligibility rule depends on observed counts. The scan explains alerts and never sets the tier. [Prospective space-time scan](https://www.satscan.org/papers/k-jrssa2001.pdf)

## Evaluation

Two calibration seeds select a threshold from a fixed grid, maximizing event sensitivity subject to at most one false Alert per site-month. Precision and then higher threshold break ties. Test seeds use separate random draws and different noise, seasonality, outage and event-size settings. Named replays are separate from both sets. Watch and Action are excluded from the primary Alert metrics.

The first 365 days establish history. Scoring uses the next 365 days per seed. An alert matches a labeled event when its site, syndrome and date fall within the injected event. The absence comparator is syndrome-agnostic. Each alert is credited to at most one event. A cluster may produce multiple true alerts at different sites. Event sensitivity counts each detected event once. Paired lead time uses the first matching alert from both systems. The clinical-threshold marker is the first day with at least 12 injected syndrome counts across the event sites. It is an evaluation convention.

Comparators use a seven-day EARS C2 baseline with a two-day guard band for absence, one-sided CUSUM of standardized syndrome counts, and fixed environmental thresholds for respiratory and heat. The environmental comparator cannot identify GI. Comparator alerts have a three-day per-unit cooldown. [CDC EARS evaluation](https://stacks.cdc.gov/view/cdc/3209/cdc_3209_DS1.pdf)

Ablations remove environmental, clinical or workplace feeds, aggregate to districts, delay outcomes by two days, and apply multiplicative count noise with 30% standard deviation. The district ablation measures false alerts per district-month. The report separates local fit time, batch scoring time and ingest-to-scored-snapshot latency. These timings exclude upstream reporting delays and network transit.

## Findings and limits

Canary found 128 of 144 simulated events with 14 false Alerts. It gained a median day over absence EARS C2 where both found an event. Clinic CUSUM detected more events and led by a median day on paired events. The fixed hazard rule led by a median of three days on paired events and also fired on unrelated exposure spikes. Against the simulated clinical marker, the median Canary Alert was one day after the threshold. Removing the clinical feed reduced sensitivity to 27.1%.

The simulator assumes particular exposure-to-outcome relationships and uses approximate day-level reporting. Its ground truth, offsets, geographic links and prevalence are generated. The two-day delay ablation shifts outcome availability in a retrospective series. It does not reconstruct source-system arrival timestamps. A pilot would need independent health and operations data, availability timestamps, approved operating thresholds and a prospective comparison. Use the reported precision and lead times as properties of this evaluation setup.

The executable harness lives in `eval/backtest.py`. Its scoring functions take a daily aggregate dataset and independent labeled events. The report and chart are generated by `uv run python -m eval.backtest`. [Report JSON](../eval/reports/summary.json)

After intentionally updating the checked-in report, copy it to `frontend/src/lib/data/validation-report.json` so the demo displays the same run. Frontend CI checks the two files for equality.
